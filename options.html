    Chrome 本地网络访问限制（LNA）

    Chrome 142 起，公网页面请求本机 / 内网地址会被浏览器强制拦截，典型表现是「诊断里显示规则已生效，但页面请求失败」， 控制台报 more-private address space 或 Permission was denied ... loopback。 这不是规则没生效，扩展也无法绕过。填入发起页面的地址，生成一次性放行命令：

    • 不想改浏览器设置时，可以把文件放进扩展目录的 local/，Response 写成 file:///local/文件名：走扩展内部资源，不经过网络栈，不受 LNA 限制（已实测）。
    • 仓库自带 tools/apply-lna-policy.ps1，可直接把某个来源写入策略，无需手敲 reg 命令。
    • 修改启动参数或策略后，必须完全退出 Chrome（包括后台进程）再启动才会生效。

    Manifest V3 下的行为差异

    • 规则由 declarativeNetRequest 直接执行，不再经过扩展进程，因此比旧版更稳，但只能做「URL → URL」重定向。
    • Chrome 不允许扩展把请求重定向到 file://。本地文件请改用本地 HTTP 服务（如 http://127.0.0.1:5500），或把文件放进扩展目录的 local/，规则写成 file:///local/app.js。
    • 不支持 (?=)、(?!)、(?<=) 与反向引用，这类正则在 RE2 引擎下会报错。
    • 同一请求只会被优先级最高的一条规则重定向，旧版「多条规则链式替换」不再生效，请把一条规则写完整。
